## Notes for the reviewer

- **Counting method for row 1.** A literal `cmd!(` occurrence count gives 394, which includes 5
  macro-definition arms in `mod.rs` and 4 helper-macro bodies (`toggle!`, `flag!`, `radio!`,
  `option!`). Excluding those leaves 385 literal commands (including 9 `cmd!(view …)` calls).
  Adding the 94 helper invocations and the one direct `CommandSpec` gives **480**. The previous
  skill's 395 therefore undercounted; the tag-to-tag diff shows no command id added or removed.
- **Other claims checked but not tabulated:** 66 UI commands vs 480 engine ids (no overlap);
  512-line menu catalog; 397/512 engine menu leaves and 482/512 with UI aliases (repo report,
  not re-run); English-only UI with a Hangul fallback (`crates/ui-egui/src/fonts.rs`) while
  `docs/localization-parity.md` denies it; Workspace is a minimal one-folder list
  (`crates/ui-egui/src/windows.rs` `workspace`); no speech-to-text or fidelity harness
  (`docs/gaps.md` G-07/G-18).
- **No build, no GUI launch, no audio-device or runtime test.** The installed app's `--version`
  was executed (prints `SoundCraft 0.12.1`) and the bundle's `Info.plist` and signature
  entitlements were read; everything else is static evidence from the v0.12.1 tree. `cargo
  xtask parity` was not re-run, so the 397/482 menu numbers are the repo's report, not a fresh
  measurement.
- **Doc/code divergences labelled:** plugin count (`docs/plugin-parity.md` 26+2 vs 24+3),
  takes-in-RAM/no-device-choice (`docs/gaps.md` G-06, `docs/roadmap.md` alpha gate,
  `docs/architecture.md`), track presets and MIDI controllers/filter
  (`docs/file-format-parity.md`), Hangul fallback (`docs/localization-parity.md`), and the
  Workspace window (minimal folder list despite G-16 saying no browser).
- **Uncertain / not runtime-verified:** (a) whether `ui.audio_device` works reliably on this macOS
  build — `docs/hardware-parity.md` says "not yet verified on macOS"; (b) whether a device change
  preserves third-party plug-in state — `apply_audio_config` rebuilds the player without calling
  `capture_plugin_states`, so the skill advises saving first; (c) UI automation behaviour
  (`ui.click`/`ui.drag`/`ui.screenshot`) was read from code, not exercised; (d) `ui.scroll`/`ui.zoom`
  CLI misrouting was derived from `is_control_method`, not run.
- **Tier legend:** implemented = code path wired into UI/CLI; partial = code exists but a known
  capability is missing or unverified; claimed-not-found = only docs/README mention it. No row here
  is claimed-not-found; all documented claims were located in code unless marked stale.
