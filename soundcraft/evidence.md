## Notes for the reviewer

- **Counting method for row 1 (re-derived, not copied).** A literal `cmd!(` grep gives 397 at this
  tag, of which 6 are in `mod.rs` (4 macro-expansion arms, 1 doc-comment line, 1 `#[cfg(test)]`
  panic probe); the four helper macros each contain one `cmd!` in their bodies, so **387** literal
  production ids remain. Adding the 94 helper invocations and the 1 direct `CommandSpec` gives
  **482**. The same script run over a read-only fetch of tag `v0.12.1` gives 480 with no duplicate
  ids at either pin; the id diff is exactly `+clip.auto_rename`, `+edit.strip_silence_preview`.
- **Baseline corrections.** (a) The previous skill's 480 / 66 / 17 / 17 / 27 counts were correct for
  v0.12.1; only the *new* counts differ. (b) It said there is "no per-channel hardware routing":
  `track.input` + `plan_takes` do map a track to consecutive device channels, so the correct
  limitation is the missing I/O matrix, per-channel gain/delay and latency reporting. (c) It said
  `--no-audio` disables output but not input: `ensure_input` returns early when no player exists, so
  no input device opens either (same code at v0.12.1).
- **Doc/code divergences labelled in SKILL.md:** `docs/roadmap.md` alpha gate still claims "no input
  device choice"; `docs/gaps.md` G-16 lists track-preset recall UI as missing (commands exist, the
  browser does not); `docs/localization-parity.md` denies the Hangul fallback; `docs/gaps.md` G-06 /
  `docs/architecture.md` describe takes in RAM (true for the session pool, not for the recording
  write path); engine menu parity 397/512 is the repo's generated report, not re-run here.
- **No build, no GUI launch, no audio-device or runtime test.** The installed app's `--version` was
  executed (prints `SoundCraft 0.13.1`) and the bundle's `Info.plist` was read; everything else is
  static evidence from the v0.13.1 tree plus a read-only diff against the v0.12.1 tag for change
  attribution.
- **Uncertain / not runtime-verified:** (a) whether `ui.audio_device` works reliably on this macOS
  build — `docs/hardware-parity.md` still says "not yet verified on macOS"; (b) whether a device
  change preserves third-party plug-in state — `apply_audio_config` closes editors and rebuilds the
  player without capturing states first, so the skill advises saving; (c) UI automation behaviour
  (`ui.click`/`ui.drag`/`ui.screenshot`/`view.scroll_into_view`) read from code, not exercised;
  (d) the `ui.scroll`/`ui.zoom` CLI misrouting, derived from `is_control_method`; (e) exact
