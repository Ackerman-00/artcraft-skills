## Overview

CADCraft is an open-source (MIT OR Apache-2.0) 2D CAD and drafting application written in Rust (egui/eframe, wgpu) for macOS, Windows, Linux, FreeBSD and the web; source is GitHub `storytold/cadcraft` (`README.md`, `Cargo.toml`, `LICENSE-MIT`, `LICENSE-APACHE`). It is a clean-room reimplementation of Autodesk AutoCAD targeting AutoCAD 2027, 2D drafting first (`AGENTS.md` clean-room rules, `docs/target-app-parity.md`). Stage: **pre-alpha** — four of AutoCAD's five core workflows fail the alpha gate (`ROADMAP.md:3`). Scale at this tag: ≈162,600 lines of Rust outside `*/tests/` in 12 library crates, 3 apps and `xtask`; workspace version 0.13.0, edition 2024, `rust-version` 1.90 (`Cargo.toml`).

The differentiator: every user-visible action is a command. The engine registry holds **441** commands (`crates/engine/src/cmd/mod.rs:171`; count from the repo-generated `docs/parity-checklist.md:7`), the desktop app's catalog adds **57** UI-only entries for **498** total (`crates/ui-egui/src/menus.rs:17`, `crates/ui-egui/src/control.rs:225`), and the same ids are reachable from the command line, the JSON control channel, the MCP server and `cadcraft-cli`.

**Release delta vs v0.11.0 (measured, not copied).** Registered commands **427 → 441** (+14); menu breadth **283/491 (58%) → 296/491 (60%)**; static `CommandSpec::new(` sites **415 → 425**; UI-only commands **56 → 57**; MCP tools 15 and control methods 27 app / 12 headless are **unchanged**; CLI verbs **7**, unchanged; `acadrust` **0.6.4 → 0.6.5** (`crates/dwg/Cargo.toml`). Landed per the dated log in `docs/gaps.md:153-156`: `COMPAREEXPORT` (a comparison exported as a new grouped drawing, 2026-10-24) and `DIMTFILL`/`DIMTFILLCLR` dimension text backgrounds including DXF groups 69/70 (2026-10-24/25); APPLOAD gained a `.lsp` file browser (2026-10-22, `#1820`). The control channel now **requires a per-session token** on every request (`crates/mcp/src/control_token.rs`, `docs/control-protocol.md`) — the v0.11.0 skill documented no token, so hand-written clients need updating.

**Why 425 sites but 441 commands** — do not "correct" one number to the other: two `CommandSpec::new(` occurrences are the bodies of the `gc!`/`dc!` macros, and those macros are invoked 18 times (12 `gc!`, 6 `dc!`) in `crates/engine/src/cmd/constraints.rs:20-35`. 425 − 2 + 18 = 441, which matches the generated checklist exactly. Quote the generated/live number for capability claims.

## Capabilities (verified)

Everything below is implemented and wired to a command/CLI/MCP/control surface unless marked **partial** or **claimed**; `evidence.md` gives the per-claim tier.

### Drawing, editing and precision

- **Draw:** LINE, PLINE (arcs, widths), CIRCLE (center/radius/diameter, 2P, 3P), ARC, RECTANG (fillet/chamfer), POLYGON, ELLIPSE (+arcs), SPLINE, POINT, XLINE, RAY, DONUT, TEXT, MTEXT, plus MLINE, REGION and HELIX (`crates/engine/src/cmd/draw.rs`, `crates/engine/src/cmd/draw2.rs`, `crates/engine/src/cmd/draw2/mline.rs`).
- **Modify:** ERASE, MOVE, COPY, ROTATE, SCALE, MIRROR, STRETCH (window/crossing polygons, BOX, fence), OFFSET, TRIM, EXTEND, FILLET, CHAMFER, BREAK, JOIN, EXPLODE, rectangular/polar ARRAY (associative, ARRAYEDIT; ARRAYPATH exists but is not associative), draw order, OVERKILL, LENGTHEN, ALIGN, REVERSE, FLATTEN, CHSPACE; Express Tools NCOPY, BREAKLINE, TXT2MTXT, BURST, MOCORO (`crates/engine/src/cmd/modify.rs`, `crates/engine/src/cmd/modify2.rs`, `crates/engine/src/cmd/array/`, `crates/engine/src/cmd/overkill.rs`, `crates/engine/src/cmd/draw2/breakline.rs`, `crates/engine/src/cmd/txt2mtxt.rs`, `crates/engine/src/cmd/blocks/burst.rs`).
- **Precision:** 14 object snaps — endpoint, midpoint, center, geometric center, node, quadrant, intersection, extension, insertion, perpendicular, parallel, tangent, nearest, apparent intersection — with deferred tangent/perpendicular for a line's first point; object snap tracking; polar tracking; ortho (hold Shift to invert); grid snap; direct distance entry; `@dx,dy`, `@d<a`, `#x,y`; point modifiers FROM/M2P/TK; typed snap overrides (`crates/engine/src/snap.rs:34` `ALL: [(u32, &str); 14]`, `crates/engine/src/snap/tracking.rs`, `crates/engine/src/pointmod.rs`).
- **Command line and grips:** prompts with clickable keywords, history (F2), AutoComplete, aliases (`.pgp` + ALIASEDIT/REINIT), transparent commands, `.scr` scripts; hot grips cycle Stretch/Move/Rotate/Scale/Mirror with Space, with Base point, Copy, Reference and Undo options (`crates/engine/src/cmd/griphot.rs`, `crates/engine/src/cmd/file/pgp.rs`). AutoComplete and right-click repeat have code and tests but were not exercised in a live window in this audit.
- **Layers and properties:** Layers palette and Layer Properties Manager, layer tools (isolate/freeze/off/lock/match/previous/merge/delete), saved layer states, Properties palette, linetypes, lineweights, ACI/true colour, transparency, OPTIONS dialog with persisted profiles (`crates/engine/src/cmd/layer/`, `crates/engine/src/cmd/props.rs`, `crates/ui-egui/src/options/`; `docs/gaps.md` F20).
- **Annotation:** the DIM* family — linear, aligned, angular, arc, diameter, radius, ordinate, jogged, continue, baseline, QDIM, DIMEDIT/DIMTEDIT, DIMBREAK, DIMINSPECT, DIMSTYLE create/update/override, DIMREASSOCIATE/DIMDISASSOCIATE with associative dimensions, and DIMTFILL/DIMTFILLCLR text backgrounds; MLEADER plus MLEADEREDIT/ALIGN/COLLECT and MLEADERSTYLE; TABLE with formulas, cell styles, TABLEDIT/TABLEEXPORT, table breaking and CSV data links; TOLERANCE feature-control frames; annotative scaling (SCALELISTEDIT, OBJECTSCALE, ANNOVISIBLE); on-canvas MTEXT editor with formatting toolbar; QuickCalc palette (UI-only, Cmd+8); COMPARE and COMPAREEXPORT (`crates/engine/src/cmd/annotate*.rs`, `crates/engine/src/cmd/mleader*.rs`, `crates/engine/src/cmd/table/`, `crates/engine/src/cmd/tolerance.rs`, `crates/engine/src/cmd/annoscale.rs`, `crates/engine/src/cmd/file/compare/`, `crates/ui-egui/src/palettes/quickcalc.rs`; `docs/gaps.md` F7–F12).
- **Hatch, blocks, xrefs:** pick-point HATCH with islands, HATCHEDIT boundary add/remove, **23** standard patterns, solid and gradient fills, user `.pat` files; BLOCK/INSERT/ATTDEF, BATTMAN, ATTSYNC, ATTEDIT, DATAEXTRACTION/EATTEXT, nested blocks, groups, WBLOCK, PURGE; xrefs (XATTACH, -XREF, XBIND, XOPEN, overlays, relative paths); Block Editor for static blocks (BEDIT/BSAVE/BSAVEAS/BCLOSE); REFEDIT/REFSET/REFCLOSE in-place block-reference editing; dynamic blocks read from other files with visibility/lookup/custom-property edits and grips (`crates/doc/src/library.rs:100` `standard_patterns`, `crates/engine/src/cmd/hatch/`, `crates/engine/src/cmd/blocks/` incl. `crates/engine/src/cmd/blocks/bedit.rs`, `crates/engine/src/cmd/blocks/refedit.rs`, `crates/engine/src/cmd/blocks/dyngrip.rs`; `docs/gaps.md` F2, F3, F13).

### Files and formats (exact, from code)

- **Open/read:** DXF ASCII R12–2018 (one reader, no version gating) and binary R13+ (R12 binary is not read); pre-2007 files decode from `$DWGCODEPAGE` (`crates/io/src/lib.rs:62` `read()`, `crates/io/src/dxf_read.rs`, `crates/dxf/src/lib.rs:350` binary parse, `crates/dxf/src/codepage.rs`). DWG by content magic `AC10xx` through the `acadrust` **0.6.5** bridge (MPL-2.0, unmodified; R13/R14 untested, pre-R13 not read) (`crates/dwg/src/lib.rs:30` `VERSIONS`, `:35` `is_dwg`, `crates/dwg/Cargo.toml`). SVG and gzipped SVGZ (shapes, paths, groups, Inkscape layers; no CSS, `use`, fills/gradients/patterns, text, images, `rx`/`ry`; all but fills/gradients/patterns are named in a read note) (`crates/io/src/svg_read.rs:1-15`; `docs/gaps.md` FF14).
- **Save/native:** DXF is the native path — ASCII or binary, versions 2000–2018 (default: the file's own `$ACADVER`, 2018 for a new drawing; a binary DXF stays binary on QSAVE) (`crates/io/src/lib.rs:86` `write_with()`, `crates/dxf/src/version.rs:7-20`, `crates/engine/src/cmd/file.rs:588`). DWG write 2000–2018, at least 2004 unless 2000 is explicitly asked for (`crates/io/src/lib.rs:86-100`). `.dwt` templates save via SAVEAS (written as DWG content); NEW/QNEW accept `.dwt`/`.dxf` templates (`crates/io/src/lib.rs:113`, `crates/engine/src/cmd/file.rs`; `docs/file-format-parity.md` FF3).
- **Unmodelled content:** DXF writes back unknown entities/objects, foreign xdata, extension dictionaries, reactors, layer states and colour books (#528); through **DWG** the bridge still drops custom-class entities/objects, xdata on table records and blocks, entity colour books and reactors. SAVE/SAVEAS report what the target cannot hold in a `notSaved` field plus a command-line message, and `cadcraft-cli` writes the same warning to stderr for `.dwg`/`.dwt` output (`crates/engine/src/cmd/file.rs:517-575`, `apps/cadcraft-cli/src/main.rs:236-244`; `docs/gaps.md` FF1).
- **Import:** another DXF/DWG's objects via `import {path|data, at?, scale?}`; user `.lin` linetypes, `.pat` hatch patterns and `.pgp` aliases (`crates/engine/src/cmd/exchange.rs:34`, `crates/engine/src/cmd/props/linfile.rs`, `crates/engine/src/cmd/hatch/patfile.rs`, `crates/engine/src/cmd/file/pgp.rs`). SVG/SVGZ is read by `open`, not by `import`; SVG geometry becomes centre-line entities in millimetres with the page's top-left corner at the origin and Y up. Stored xref/data-link paths resolve through `craft-docpath` (`craft-libs` rev `6e7f28518dd1cb57e1624bdc269c3c14316b13ae`): only local files or the document's own network share open; paths to other computers, device paths and non-file URLs are refused (`crates/engine/src/doc_path.rs:1-11`).
- **Export:** SVG; PNG 2400×1600 (framed window or extents); vector PDF with embedded TrueType text subsets, OCG layers, multi-sheet output, hyperlinks and plotted transparency. Commands EXPORT, EXPORTPDF, PUBLISH, PDFBOOK, PLOT, PREVIEW and `cadcraft-cli convert`; EXPORT/PUBLISH/PDFBOOK return base64 `data` when no path is given (`crates/io/src/lib.rs:113` `write_framed()`, `crates/io/src/pdf.rs`, `crates/engine/src/cmd/exchange.rs:38-55`, `crates/engine/src/cmd/layout.rs:79-88`). CLI image/PDF export always renders **model space**; paper-space sheets go through PLOT/EXPORTPDF/PUBLISH. Image export warns on stderr about model-space entities it cannot draw (`apps/cadcraft-cli/src/main.rs:297`).

### Automation surfaces (all over the same command registry)

- **Command catalog.** `engine.commands` / `cadcraft-cli commands` return id, label, menu path, shortcut, aliases, parameter docs and enabled state. Headless/CLI catalog = **441** engine commands; the desktop app's catalog adds **57** `UI_COMMANDS` (**498** entries) (`crates/engine/src/cmd/mod.rs:171`, `crates/ui-egui/src/menus.rs:17`, `crates/ui-egui/src/control.rs:225`). Ids are AutoCAD command names lower-cased; alias resolution prefers command ids, then user aliases, then built-in aliases (`crates/engine/src/cmd/mod.rs` `resolve_alias`).
- **MCP server (stdio).** `cadcraft-cli mcp` (headless in-process session) or `cadcraft-cli mcp --connect 127.0.0.1:PORT [--lazy] [--launch]` (bridged to the running app; `--launch` opens CADCraft on macOS). `--lazy`/`--launch` require `--connect`; with an unreachable app the call fails with a remedy, never a silent separate drawing (`docs/mcp.md`, `crates/mcp/src/backend.rs:129-142`, `apps/cadcraft-cli/src/main.rs:730-760`). **15 tools** — 12 headless, plus 3 only when connected to the app:

| Tool | Purpose |
|---|---|
| `command_line {text}` | Type at the prompt like a user; spaces act as Enter, empty text = Enter. |
| `script {text}` | Run a multi-line `.scr`-style script. |
| `execute {command, params}` | Any engine command in JSON form; never opens a dialog. |
| `list_commands {filter?}` | Command catalog; filter matches id, label and aliases. |
| `inspect_drawing {entities?, limit?}` | Counts, extents, layers, styles, blocks, layouts, selection, undo, `skipped`. |
| `query_entities {type?, layer?, selected?, window?, crossing?, limit?, offset?}` | Entity pages with handles and geometry; `count` is all matches. |
| `render {width?, height?, fit?, window?, path?}` | PNG of the drawing, returned as image content. |
| `find_text {contains?, layer?, window?, limit?, offset?}` | TEXT/MTEXT/attributes/multileaders with position, height, rotation, style. |
| `new_drawing {metric?}` | New imperial or metric drawing. |
| `open {path}` | Open a drawing (whatever `open` reads). |
| `save {path?}` | Save DXF/DWG; a `.svg`/`.png`/`.pdf` path exports instead. |
| `cancel` | Escape: cancel the running command or clear selection. |
| `screenshot {path?}` *(app only)* | Window PNG; needs a presented frame. |
| `ui_inspect` *(app only)* | Panels, canvas rect, view, cursor, snap, focus, performance. |
| `ui_click {x, y, space?, button?}` *(app only)* | Click in the drawing area; right button = Enter. |

  Resources: `cadcraft://drawing` and `cadcraft://commands`. Arguments are schema-checked (bad/missing arguments are JSON-RPC `-32602`; a failing tool is an `isError` result) (`crates/mcp/src/tools.rs:9-44`, `crates/mcp/src/server.rs:119-126`).
- **JSON control channel.** Desktop app with `--control PORT` (or `CADCRAFT_CONTROL_PORT`); one JSON object per line over `127.0.0.1:PORT`. **Every request must carry `"token": "<session token>"`** or the reply is `{"ok": false, "error": "unauthorized: missing or invalid control token", "state": "not-run"}` and the connection closes. The app prints a random 256-bit token at startup to an owner-only file, `cadcraft-control-<port>.token`, in `$XDG_RUNTIME_DIR` (else `~/.cache`; `%LOCALAPPDATA%` on Windows); its path is logged at startup. Read that file yourself — the MCP bridge does it automatically (`crates/mcp/src/control_token.rs:22`, `apps/cadcraft/src/control_server.rs:52-70`, `docs/control-protocol.md`). **27 top-level methods** in the app, **12** in headless mode: `cmdline.input/script/key/state`, `engine.execute` (alias `command`), `engine.commands`, `drawing.inspect`, `ui.inspect`, `ui.elements`, `ui.menu.list`/`invoke`, `ui.pointer`, `ui.click`, `ui.move`, `ui.drag`, `ui.key`, `ui.text`, `ui.set`, `ui.resize`, `ui.focus`, `ui.screenshot`, `ui.render`, `app.open`/`save`/`quit`, `control.methods`, `ping` (`crates/ui-egui/src/control.rs:191-219`; headless list `crates/mcp/src/backend.rs:251-263`). Limits: 16 connections, 64 queued requests, 256 MiB/line, 60 s reply timeout (`state: not-run` = safe to resend, `may-have-run` = inspect first), 10 min idle, 30 s blocked-write timeout (`apps/cadcraft/src/control_server.rs:22-47`). Panel docking (`ui.dock`/`ui.dock.reset`) and `entities {selected:true}` run through `engine.execute`, not as top-level methods. `ui.set` merges any `UiState` field (palettes, `theme`, `animations`, `saveFormat`, `saveVersion`, `systemCursor`, `interfaceLanguage`). The app's `engine.execute` also runs UI commands; headless runs engine commands only.
- **CLI `cadcraft-cli`** (not inside `/Applications/CADCraft.app`; it ships in the separate `cadcraft-cli-<ver>-macos-universal.zip`): **7 verbs** — `info`, `convert`, `run`, `commands`, `mcp`, `perf`, `sample` — plus `--version`/`--help`. Usage and framing text: `apps/cadcraft-cli/src/main.rs:66-92`; unknown options are rejected per verb (`validate_options`).

| `convert IN OUT.(dxf\|dwg\|svg\|png\|pdf) [--window x0,y0,x1,y1 \| --view extents\|current]` | Format conversion / image export; PNG 2400×1600; model space only. |

- **Scripting and import automation:** `.scr` via SCRIPT or `run --script-file`; AutoLISP via `lisp {code, inputs?}` / `appload {path | name, data}`; `.pgp` via `aliasedit`/`reinit`; `.lin` via `linetype {load, file | text, reload?}`; `.pat` via HATCH's `patternFile`/`patternText` or by typing a `.pat` name at its pattern prompt. `import` brings another DXF/DWG's objects in; `export` returns bytes/base64 when `path` is omitted; `document.bytes {format, version, binary}` returns base64 without touching a file (`crates/engine/src/cmd/file.rs:184`, `crates/engine/src/cmd/exchange.rs:33-41`).
- **Read-back commands for agents:** `drawing.inspect` (summary + `skipped{count,sections}`), `entities` (filters/paging/`selected:true`), `texts` (readable text, formatting removed), `shapes` (perimeter/area/centroid/winding/self-intersection/`selfCheck` for closed polylines, circles, full ellipses, closed splines), `usage` (cross-reference of layers/blocks/styles/linetypes, with `unused` for PURGE), `loops` (implied closed loops from loose LINE/ARC chains, with gaps), `countlist`/`counttable`/`count`, `properties`, `list`, `dist`, `id`, `area` (`crates/engine/src/cmd/inquiry.rs:54-55` for `usage`/`loops`; `crates/engine/src/cmd/inquiry/shapes.rs`, `crates/engine/src/cmd/inquiry/loops.rs`).

### Platform notes

- Native macOS universal app (signed, notarized DMG; CLI in a separate signed zip), Windows x64/arm64/x86 MSI (DirectX 12 default, `WGPU_BACKEND` to override), Linux x86_64/aarch64/riscv64 in AppImage/Flatpak/deb/rpm/tar, FreeBSD x86_64 tar (`README.md` Downloads; `packaging/macos/package.sh:43-44`).
- WebAssembly build runs the same UI (WebGPU, `?webgl` WebGL2 fallback, `?cpu` canvas mode, `?sample`, `?host=parent` same-origin postMessage bridge). **No DWG**, no autosave, and saves are browser downloads (`apps/cadcraft-web/src/main.rs:1-9`; `docs/gaps.md` F4, FF12).
- **16 interface languages**: English, Greek, Ukrainian, Brazilian Portuguese, German, Spanish, Czech, Russian, French, Simplified Chinese, Italian, Korean, Swedish, Arabic, Hungarian, Turkish; live switching via `ui.language` (`auto,en,el,uk,pt-BR,de,es,cs,ru,fr,zh,it,ko,sv,ar,hu,tr`), also `CADCRAFT_LOCALE` (`crates/ui-egui/src/i18n/mod.rs:190`, `docs/localization.md`). CJK/Arabic/Hangul need an installed matching font; engine messages and CLI/MCP replies stay English. README's status table still lists 15 and omits Greek.
- Accessibility: the canvas hides the system cursor and draws its own crosshair — `View ▸ Accessibility ▸ Show System Cursor` / `CADCRAFT_SYSTEM_CURSOR=1` / `ui.set {"systemCursor": true}` restores it; animation effects follow the OS setting unless forced (`View ▸ Accessibility ▸ Animation Effects`, `ui.set {"animations": "on"|"off"|"system"}`, reported by `ui.inspect`) (`README.md` Accessibility, `crates/ui-egui/src/options/`).
- 3Dconnexion SpaceMouse motion is compiled for Windows/Linux only; the macOS build has status/buttons but no motion (`apps/cadcraft/src/spacemouse.rs` cfg gates; `docs/hardware-parity.md` still lists 3D mice as absent).

## Known limitations and not-implemented

Read `docs/gaps.md` (the maintained work list, last updated 2026-10-25) before promising anything. `ROADMAP.md:22` still quotes an older 245/491 (50%) menu measurement from 2026-10-10 (and mixes UI-only commands into it, so it is not comparable) — the generated checklist says 296/491 (60%), with 195 reference items uncovered (`docs/parity-checklist.md`). The high-impact limits for an agent:

- **Saving DWG is lossy.** The acadrust bridge drops custom-class entities/objects, xdata on table records and blocks, entity colour books and reactors; DXF keeps unmodelled content raw. Always check the `notSaved` report on every DWG save (`docs/gaps.md` row 1, FF1; `docs/file-format-parity.md`).
- **No real-file corpus and no AutoCAD verification.** All file tests are synthetic (36 of them); no CADCraft output has been checked in AutoCAD black-box (`docs/gaps.md` FF5). A 10 MB DWG took ~2 min to fail (#57); size limits stop runaway conversions, throughput does not (`docs/gaps.md` FF6; `crates/dwg/src/lib.rs:8-22`).
- **No 3D at all.** No UCS, 3D views, orbit, solids, surfaces, meshes, sections, visual styles, materials, lights or rendering (`docs/gaps.md` F24). `3DORBIT`, `ATTACH` and `SHARE` are registered only to refuse: "3DORBIT is not available yet: CADCraft draws in 2D (plan view) only", "ATTACH is not available yet: raster images and PDF/DWF/DGN underlays can't be shown yet" (`crates/engine/src/cmd/exchange.rs:56-70`). README's tagline says "2D and 3D"; the 3D half is not implemented.
- **Curve geometry is tessellated.** Ellipse/spline intersections, offsets, trims, closest points and snaps are approximations; polyline offsets ignore bulges; tolerances are absolute (one `EPS`), and survey-scale coordinates are untested (`docs/geometry-parity.md`; `docs/gaps.md` row 3).
- **XCLIP is missing; xrefs cannot be edited in place.** XOPEN opens the source; REFEDIT edits block references only (an xref is refused with a message, `crates/engine/src/cmd/blocks/refedit.rs:117`). No dynamic-block authoring (parameters/actions); references from other files can change visibility states, lookups, distances and positions through custom properties and grips (`docs/gaps.md` F2, F3).
- **SHX fonts are not parsed.** SHX-style text draws with CADCraft's stroke font or `FONTALT`, so metrics differ from AutoCAD; SHX shapes in linetypes are skipped (`README.md` Fonts; `docs/gaps.md` FF8/FF9).
- **No PDF import/underlays, no raster image attach/display** (IMAGE entities and definitions round-trip but pixels never load), no DWF/DGN/WMF/EPS/ACIS/STL exchange, no DWS standards, no system printers (`docs/gaps.md` FF10/FF11, H3; `docs/file-format-parity.md` "Other formats").
- **Binary plot files are unread.** `.ctb`/`.stb`/`.pc3`/`.pmp` must be recreated in CADCraft's JSON formats; plot styles and device papers work otherwise (`docs/gaps.md` F14, FF9).
- **MTEXT editing is partial.** `TEXTEDIT` (alias `DDEDIT`) replaces TEXT/MTEXT/ATTDEF/dimension text by handle, but there is no in-place formatting editor for an existing MTEXT, no fields (FIELD), no spell check, and stacked fractions show as placeholders (`crates/engine/src/cmd/modify2.rs`; `docs/gaps.md` F9).
- **No autosave in the web build.** Desktop autosave writes DXF `.sv$` files (SAVETIME default 10 min, 0 off, max 600 minutes, SAVEFILEPATH), Drawing Recovery lists them, and AUDITCTL=1 makes AUDIT write an `.adt` log; the web build has none (`crates/engine/src/autosave.rs:24-31`, `crates/engine/src/cmd/audit.rs`; `docs/gaps.md` F4).
- **SETVAR covers ~150 of ~1,000 variables**; no Sheet Set Manager, eTransmit, Traces, Markup Import, CUI(x) or workspaces (`docs/gaps.md` F23, U10, U12). No DIMSTYLE manager dialog, and DIMSTYLE variables are partial (F7).
- **macOS Finder file association for `.dxf` is broken (#158)**; open positionally or via File > Open (`docs/gaps.md` U13, P3).
- **PR quality-gate status is uncertain, and the gap row is stale.** `.github/workflows/ci.yml` triggers on every pull request and push to `main` and calls the suite's shared `gate.yml@main` from `storytold/craft-common-actions`, whose comment names `cargo xtask ci` (fmt, clippy, tests, assets, layers, wasm); `docs/gaps.md` S1 still says no PR runs it — the workflow is newer than that row. The shared gate lives in another repo and was not inspected, so whether it passes today is uncertain — check `.github/workflows/ci.yml` and the PR's checks. Also present: packaging lint, release builds, Nix/FreeBSD/Windows-ARM builds, SonarCloud analysis.
- **No plug-in API.** ObjectARX/.NET plug-ins cannot load; a Rust→WebAssembly plug-in API is planned, not built. What an agent can extend today is AutoLISP, `.scr` scripts (SCRIPT), `.pgp` aliases, `.lin` linetypes and `.pat` patterns (`docs/customization.md`; `docs/gaps.md` E4).
- **Web PLOT may show raw PDF bytes (#134)**; Windows/Linux get little runtime testing (`docs/gaps.md` S4, P1/P2).
- **Claimed but unverified here (static reading only):** README's interactive-feel claims (AutoComplete, right-click repeat), "every arrowhead", associative-dimension behaviour, MTEXT bidi/OpenType shaping for Arabic-script text, per-language font availability, and SpaceMouse behaviour on Windows/Linux. Anything absent from both code and `docs/gaps.md` should also be treated as claimed-but-unverified.

## How to operate

**Launch (macOS).** GUI binary is inside `/Applications/CADCraft.app` (`Contents/MacOS/CADCraft`); launch with `open -a "CADCraft"`. Start flags (`apps/cadcraft/src/main.rs:243-258`): `--control <port>` (a bare `--control` reuses `CADCRAFT_CONTROL_PORT`), `--sample`, `--version`/`-V`, and positional drawing paths (each opens; prefer this over Finder drag, see P3). CADCraft's own MCP `--launch` runs `open -a CADCraft --args --control PORT` (`crates/mcp/src/backend.rs`). **The bundle contains no CLI binary** — install `cadcraft-cli` from `cadcraft-cli-<ver>-macos-universal.zip` (`packaging/macos/package.sh:43-44`, `README.md` Downloads). CADCraft does not have to be running for `cadcraft-cli` or headless MCP.

Environment variables that matter: `CADCRAFT_CONTROL_PORT`, `CADCRAFT_CONFIG_DIR` (isolated profile; an empty value counts as unset), `CADCRAFT_LOCALE`, `CADCRAFT_SYSTEM_CURSOR=1`, `CADCRAFT_FONTALT`/`CADCRAFT_FONTFALLBACK`, `CADCRAFT_VSYNC`, `CADCRAFT_NO_NATIVE_MENU` (macOS), `CADCRAFT_WAYLAND=1` (Linux: keep native Wayland instead of XWayland), `WGPU_BACKEND` (Windows troubleshooting), `RUST_LOG` (`cadcraft_engine=debug` logs every command-line message) (`apps/cadcraft/src/main.rs`, `README.md`).

**Settings/state (macOS).** `~/Library/Application Support/CADCraft/` holds `logs/cadcraft.log` (two rotations, 16 MiB cap), `autosave/` (`.sv$` DXF drawings), `support/` (AutoLISP startup files), and `workspace.json` (panel docking/UI choices; 64 KiB cap, versioned; invalid files are reported and left untouched) (`apps/cadcraft/src/main.rs:171-180`, `apps/cadcraft/src/workspace.rs`). The control token file lives outside it (see the control-channel bullet).

**Document model.** One window, many drawings: each open drawing is a document with its own file tab and model/paper spaces; `document.switch {index}` switches, `close {index}`/`closeall` close them. Tool Sets, Layers, Properties and External References dock, float and persist; QuickCalc opens as a floating palette (Cmd+8); the canvas is protected (`crates/engine/src/cmd/file.rs`, `crates/ui-egui/src/menus.rs`, `docs/control-protocol.md`).

**Keyboard shortcuts (from source — do not invent others).** Engine `.key()` values: Cmd+N new, Cmd+O open, Cmd+S save, Cmd+Shift+S save as, Cmd+W close, Cmd+P plot, Cmd+Z/Cmd+Shift+Z undo/redo, Cmd+C/V/X clipboard, Cmd+Shift+C copy with base point, Cmd+Shift+V paste as block, Cmd+A select all, Cmd+Shift+A PICKSTYLE, Delete clear selection, F3 osnap, F5 isoplane, F7 grid, F8 ortho, F9 snap, F10 polar, F11 object snap tracking, F12 dynamic input (`crates/engine/src/cmd/settings.rs`, `crates/engine/src/cmd/edit.rs`, `crates/engine/src/cmd/file.rs`, `crates/engine/src/cmd/layout.rs`, `crates/engine/src/cmd/groups/pick.rs`). UI-only (`crates/ui-egui/src/menus.rs`): Cmd+1 Properties, Cmd+3 Tool Sets, Cmd+8 QuickCalc, Cmd+9 command line, F1 command reference, F2 command history, Cmd+Q quit.

**Open/save/export flow.** The Open dialog filters DWG/DXF/DWT and SVG/SVGZ; the Save dialog offers DXF, DWG, DWT, SVG, PNG, PDF with the suggested name's type first (`apps/cadcraft/src/main.rs:129-166`). QSAVE/SAVE (Cmd+S) writes the drawing's own format/version; SAVEAS `{path, version?: 2000|2004|2007|2010|2013|2018, binary?: bool}`; the macOS save panel cannot pick a version per file — use SAVEAS JSON or File ▸ Default Save Format/Version (`docs/gaps.md` FF3). `document.bytes {format, version, binary}` returns base64 without touching a file. EXPORT writes dxf|dwg|svg|png|pdf; PLOT/EXPORTPDF write PDF through the plotter (paper-space sheets, page setups); PUBLISH one PDF per sheet; PDFBOOK builds ISO A-series books from frame polylines. In the web build, saves are downloads; there is no file system and no DWG (`apps/cadcraft-web/src/main.rs`).

**Headless CLI (what an agent will use most).**
```sh
cadcraft-cli info drawing.dxf                       # JSON summary: counts, extents, layers, styles, skipped…
cadcraft-cli convert drawing.dxf out.svg            # dxf|dwg|svg|png|pdf; PNG is 2400×1600
cadcraft-cli convert drawing.dwg detail.png --window 0,0,20000,15000   # frame a rectangle
cadcraft-cli run --sample --script 'CIRCLE 22,3 1\n' --save out.dxf --export out.png
cadcraft-cli run drawing.dxf --script-file setup.scr --save out.dxf
cadcraft-cli run drawing.dxf --cmd 'circle {"center":[10,10],"radius":4}' --cmd 'zoom {"mode":"extents"}' --export sel.png
cadcraft-cli run drawing.dxf --cmd 'mview {"p1":[20,20],"p2":[200,150]}' --cmd 'viewport.set {"handle":"{last}","scale":1}'
cadcraft-cli commands dim                           # command catalog (JSON), filtered
cadcraft-cli sample floorplan out.dxf               # built-in sample drawings
cadcraft-cli mcp --connect 127.0.0.1:7979           # bridge MCP to the running app
```
Framing rules: `convert` fits model-space extents; `run --export` uses the current view only if a command changed it (`zoom`, `pan`, `view.set`), else extents; `--window x0,y0,x1,y1` shows exactly that rectangle; `--view extents|current` forces one, and framing flags are refused for non-image output (`apps/cadcraft-cli/src/main.rs:260-268`). CLI PNG/SVG/PDF always render **model space** (`crates/io/src/lib.rs:113`). For paper-space output use PLOT/EXPORTPDF/PUBLISH, not `convert`.

**Command-first workflow.** Anything the UI can do is a command: `engine.execute {command, params}` runs the JSON form with no dialogs; typing (`cmdline.input`) drives the interactive prompt machines exactly like a user (spaces act as Enter except at text prompts; empty text is Enter). A refused command-line line still replies `ok: true` — check the `error` field (`crates/ui-egui/src/control.rs:302-315`). Errors inside a command never take the app down (panic guard in `crates/engine/src/guard.rs`; `Session::execute` restores the drawing, `crates/engine/src/lib.rs`). UI commands (`ui.dock`, `ui.language`, `ui.saveformat`, …) exist only in the app catalog; headless returns "unknown command" for them.

## Working with an AI agent

Legitimate and reliable:

- **Prefer the headless surfaces**: `cadcraft-cli` for one-shot work and verification, MCP (headless or bridged) for interactive sessions, the control channel when a human is watching the same window. Do not drive the GUI blindly; `ui.screenshot` needs a presented frame, so on a locked screen use `ui.render`/`render` or the CLI.
- **Talk to the control port correctly.** Read `cadcraft-control-<port>.token` (`$XDG_RUNTIME_DIR`, else `~/.cache`) and send `"token"` in every request line, or use the MCP bridge which does it for you. Never assume a local connection is authorized.
- **Author drawings programmatically**: `engine.execute` per entity, or a `.scr` script / `cadcraft-cli run --script-file`, is far more reliable than pointer simulation. Read back with `drawing.inspect`/`entities` (handles + geometry; `selected:true` reads the current selection), `texts` for room labels/titles, `shapes` for areas/centroids/self-intersections, `usage` before purging, `loops` to recover implied closed regions, and eyeball with `render`.
- **Prepare/convert inputs**: `convert` turns DXF/DWG/SVG to DXF/DWG/SVG/PNG/PDF; SVG from design tools imports as paths/groups in millimetres, page top-left at the origin, Y up (fills/gradients/patterns are silently ignored; `use`, text and images are noted on open); generate drawings with `run --save`. Check `info`'s JSON before assuming contents.
- **Interpret and repair project files**: DXF is a documented text format mapped by `crates/io/src/dxf_read.rs` / `crates/io/src/dxf_write.rs`; CADCraft-specific data (constraints, associativity, table flags, hatch gradients, plot styles, layer states, handles, multileader style) travels under the `CADCRAFT` xdata app name and `CADCRAFT_*` dictionary entries (`crates/io/src/dxf_ext.rs`). For damaged drawings use AUDIT/RECOVER; crash autosaves are `.sv$` DXF files listed by DRAWINGRECOVERY (`crates/engine/src/cmd/audit.rs`, `crates/engine/src/autosave.rs`).
- **Verify exports before reporting success**: re-open the saved file (`cadcraft-cli info`, or `open` + `drawing.inspect`), compare entity counts/extents/layers, check `open`'s `warnings`, `drawing.inspect.skipped.count`, and the `notSaved` report (CLI prints it on stderr for `.dwg`/`.dwt`). Render to PNG and look at it.
- **Report commands with their exact ids** from `engine.commands`/`cadcraft-cli commands`; ids are AutoCAD command names lower-cased. The app catalog's `ui.*` entries are not engine commands.
- **Counts to expect at v0.13.0**: 441 engine commands; 57 UI-only commands (498 in the app catalog); 15 MCP tools (12 headless + 3 app-only); 27 control methods app / 12 headless; 7 CLI verbs. Re-derive with `cadcraft-cli commands | jq length` rather than trusting any number, including the ones above.

What an agent must NOT do:

- Assume DWG saves round-trip losslessly, or that AutoCAD will open CADCraft output cleanly — nobody has verified that (see gaps). Keep an untouched copy of every received file; prefer DXF when the user's tooling allows it.
- Assume 3D/UCS, PDF underlays, raster image display, SHX metrics, dynamic-block authoring, XCLIP, xref in-place editing, Visual LISP/DCL/reactors, fields, spell check, sheet sets, eTransmit, Traces or CUI exist. Check `docs/gaps.md` first.
- Invent shortcuts, menu paths, flags or format names: only what is in `CommandSpec` (`crates/engine/src/cmd/`), `UI_COMMANDS` (`crates/ui-egui/src/menus.rs`) and the CLI usage string exists.
- Edit `.dwg` bytes or expect a CADCraft-proprietary project format — there is none; the drawing *is* the DXF/DWG.
- Send UI-only commands to a headless MCP/CLI session, or rely on `screenshot` without a presented frame.
- Call `app.quit` before saving: it quits without the unsaved-changes prompt (`crates/ui-egui/src/control.rs:502-507`).
- Trust it for production/concurrent work: pre-alpha, a synthetic-only file test suite, and open correctness issues (`docs/gaps.md` Stability; the label is "pre-alpha" for a reason).

## Verification protocol

1. Work throwaway-first: `cadcraft-cli sample bracket scratch/t.dxf` (or `run --metric`), draw, save to a scratch path, re-open, inspect, delete. Never test on the only copy of a real drawing.
2. After every save, assert on the result: the `notSaved` field / the stderr warning must be absent (it appears when the target cannot hold something). After reading, `drawing.inspect.skipped.count` must be 0 for DXF, and `open`'s `warnings` must be empty for DWG/SVG; any entry means records or objects were left out. A silent export is not a verified export (`crates/engine/src/cmd/file.rs:517-575`, `crates/engine/src/cmd/inquiry.rs:560`, `apps/cadcraft-cli/src/main.rs:236-244`).
3. Round-trip discipline: new → edit → save → close → reopen → compare counts/extents/layers; then export to PNG/SVG/PDF and look at it. For CAD-interchange files, when the user has AutoCAD or another viewer, open the file there too — CADCraft cannot yet promise interoperability.
4. Version and back up: keep each session's output under a new name or in version control; the desktop app has SAVETIME autosave, Drawing Recovery, AUDIT and RECOVER, but the web build has none, and DWG saves can drop unmodelled content.
5. Update CADCraft only between projects (launcher auto-updates), and re-check this skill's claims when the version moves — this skill describes v0.13.0.
